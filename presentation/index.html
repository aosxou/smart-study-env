💡 아키텍처 결정 기록 (ADR)

ADR-001: MQTT를 센서 데이터 브로커로 선택

상황: Arduino에서 여러 센서 데이터를 효율적으로 Backend로 전송 필요

결정: MQTT Broker (Mosquitto) 도입

근거: 낮은 네트워크 대역폭, 발행-구독 모델, 신뢰성 높음, IoT 표준

결과: 안정적인 실시간 센서 데이터 전송 확보 ✓

💡 아키텍처 결정 기록 (계속)

ADR-002: Flask를 REST API 서버로 선택

상황: 경량의 Python 웹 프레임워크로 REST API 구현 필요

결정: Flask 프레임워크 선택

근거: 학습곡선 낮음, 확장성 높음, 마이크로서비스 적합, 활발한 커뮤니티

결과: 빠른 API 개발 및 유지보수 용이 ✓

💡 아키텍처 결정 기록 (계속)

ADR-003: MediaPipe를 얼굴 인식 솔루션으로 선택

상황: 웹브라우저에서 실시간 얼굴 인식 및 포즈 분석 필요

결정: Google MediaPipe 라이브러리 선택

근거: 클라이언트 사이드 처리, 빠른 성능, 무료, 웹 지원, 높은 정확도

결과: 개인정보 보호 + 빠른 응답시간 달성 ✓

⚙️ 개발 환경 설정

1. Python 환경
cd backend pip install -r requirements.txt
2. MQTT 브로커
brew install mosquitto # macOS mosquitto # 실행
3. Arduino 설정

Arduino IDE → sensor_sketch.ino 업로드

4. 환경 변수 (.env)
ARDUINO_SERIAL_PORT=/dev/cu.usbserial-1130 MQTT_BROKER=localhost PORT=3000

⚠️ 개발 중 겪은 문제와 해결

문제 1: Arduino 시리얼 통신 불안정

해결: PySerial 라이브러리로 재시도 로직 구현

문제 2: MQTT 메시지 손실

해결: QoS 레벨 1로 설정, 재연결 정책 추가

문제 3: MediaPipe 성능 저하

해결: 프레임 스킵 및 해상도 조정

문제 4: 데이터 베이스 성능

해결: 인덱싱 추가, 쿼리 최적화
