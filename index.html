ARCHITECTURE DECISION RECORDS

기술 결정 근거

왜 이 기술을 선택했는지 — 핵심 결정 3가지.

ADR-001
MQTT 센서 브로커
✅ Mosquitto MQTT 채택
낮은 대역폭 · 발행-구독 모델 · 높은 신뢰성.
QoS 1로 연결 끊김 시에도 메시지 보장.
IoT 업계 표준으로 확장성 확보.
ADR-002
백엔드 서버
✅ Flask REST API 선택
낮은 학습곡선 · 높은 확장성.
마이크로서비스 구조에 적합한 경량 설계.
활발한 커뮤니티로 빠른 문제 해결.
ADR-003
집중도 분석
✅ MediaPipe 얼굴 인식 선택
클라이언트 처리로 개인정보 보호.
빠른 성능 · 무료 · 웹 완벽 지원.
얼굴 랜드마크 고정밀 인식으로 집중도 측정.
TROUBLESHOOTING

센서 연동 시행착오

1단계 — Arduino 연동
PySerial 데이터 수신 실패
문제시리얼 모니터엔 정상 출력, Python에서만 데이터 수신 안 됨
원인Arduino 재부팅 타이밍과 Python 연결 타이밍 불일치로 버퍼 비우기 발생
해결연결 후 2초 대기 + 첫 데이터 버리기 + 재시도 로직 추가로 안정화
2단계 — MQTT
메시지 간헐적 손실
문제네트워크 지연 발생 시 백엔드에서 센서 데이터를 간헐적으로 수신 못 함
원인QoS 0(최대 1회) 설정 — 브로커 연결 끊김 시 메시지 자동 폐기
해결QoS 1(최소 1회 보장)로 변경 + Mosquitto 영속성 활성화 + 지수 백오프 재연결 구현
3단계 — MediaPipe
웹캠 처리 성능 저하
문제1080p 해상도에서 MediaPipe 처리 시 CPU 85%+ 프레임 지연 발생
원인모든 프레임을 MediaPipe로 분석 시도 → GPU 리소스 부족
해결입력 해상도 640×480 다운스케일 + 2프레임마다 분석(프레임 스킵)으로 해결

백엔드 서버
✅ Flask REST API 선택
낮은 학습곡선 · 높은 확장성.
마이크로서비스 구조에 적합한 경량 설계.
활발한 커뮤니티로 빠른 문제 해결.
ADR-003
집중도 분석
✅ MediaPipe 얼굴 인식 선택
클라이언트 처리로 개인정보 보호.
빠른 성능 · 무료 · 웹 완벽 지원.
얼굴 랜드마크 고정밀 인식으로 집중도 측정.
TROUBLESHOOTING

센서 연동 시행착오

1단계 — Arduino 연동
PySerial 데이터 수신 실패
문제시리얼 모니터엔 정상 출력, Python에서만 데이터 수신 안 됨
원인Arduino 재부팅 타이밍과 Python 연결 타이밍 불일치로 버퍼 비우기 발생
해결연결 후 2초 대기 + 첫 데이터 버리기 + 재시도 로직 추가로 안정화
2단계 — MQTT
메시지 간헐적 손실
문제네트워크 지연 발생 시 백엔드에서 센서 데이터를 간헐적으로 수신 못 함
원인QoS 0(최대 1회) 설정 — 브로커 연결 끊김 시 메시지 자동 폐기
해결QoS 1(최소 1회 보장)로 변경 + Mosquitto 영속성 활성화 + 지수 백오프 재연결 구현
3단계 — MediaPipe
웹캠 처리 성능 저하
문제1080p 해상도에서 MediaPipe 처리 시 CPU 85%+ 프레임 지연 발생
원인모든 프레임을 MediaPipe로 분석 시도 → GPU 리소스 부족
해결입력 해상도 640×480 다운스케일 + 2프레임마다 분석(프레임 스킵)으로 해결
